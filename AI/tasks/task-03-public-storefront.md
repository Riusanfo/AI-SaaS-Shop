# Карточка задачи: Публичная витрина магазина (/:slug) и статус публикации

## Описание задачи
- **Что сделать**: Реализовать переключатель публикации магазина (`isPublished`) в панели конструктора и страницу публичной витрины `StorefrontPage.tsx` для покупателей по адресу `/:slug` на основе готового эндпоинта `GET /api/stores/public/:slug`.
- **Цель**: Обеспечить завершенный цикл работы платформы: продавец настраивает и публикует магазин, а покупатели и гости могут открыть витрину по прямой ссылке, изучить ассортимент и товары без доступа к элементам редактирования.

## План реализации
1. Добавить переключатель «Опубликовать витрину» и плашку с готовой ссылкой (`/store/:slug` или `/:slug`) с кнопкой «Скопировать» в `StoreEditor.tsx`.
2. Реализовать клиентскую страницу `StorefrontPage.tsx` с загрузкой данных через `GET /api/stores/public/:slug`.
3. Подключить рендеринг блоков витрины (`HeaderBlock`, `HeroBlock`, `ProductGridBlock`, `AboutBlock`, `FooterBlock`) в режиме «только чтение» с кнопками добавления в корзину.
4. Обработать граничные сценарии:
   - Неопубликованный магазин: отображение экрана «Магазин находится на стадии настройки и ещё не опубликован».
   - Несуществующий магазин: экран 404 «Магазин не найден».
5. Проверить `npm run lint`, `npm run build` и сквозной сценарий в браузере.

## Критерии проверки
- [ ] В `StoreEditor` работает переключение флага `isPublished` с сохранением в БД Neon.
- [ ] Публичная витрина доступна гостям и пользователям с ролью BUYER без необходимости входа в панель управления.
- [ ] Публичный эндпоинт не отдает служебные данные (ownerId, passwordHash, внутренние токены).
- [ ] `npm run lint` и `npm run build` проходят с 0 ошибок.
