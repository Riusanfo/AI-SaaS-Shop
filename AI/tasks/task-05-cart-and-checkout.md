# Карточка задачи: Корзина покупателя и тестовое оформление заказа (Sandbox Checkout)

## Описание задачи
- **Что сделать**: Реализовать модель заказа `Order` в базе данных Neon, добавить эндпоинты создания и оплаты заказа в песочнице (Sandbox), а на клиенте разработать компонент корзины `CartDrawer.tsx` и модалку оформления заказа для роли `BUYER`.
- **Цель**: Закрыть покупательский сценарий платформы и выполнить требования ТЗ по интеграции платежных сервисов (ЮKassa / CloudPayments Sandbox) и доставки (СДЭК Sandbox).

## План реализации
1. Добавить модель `Order` в `server/prisma/schema.prisma`:
   - Поля: `id`, `storeId`, `buyerId` (опционально, для гостей), `buyerEmail`, `items` (Json), `totalAmount`, `status` (`PENDING`, `PAID`, `CANCELLED`), `deliveryAddress`, `createdAt`.
   - Внешний ключ на `Store` с каскадным удалением и индекс `@@index([storeId])`.
   - Накатить миграцию Prisma: `add_orders_table`.
2. Реализовать серверные роуты `server/src/routes/orders.ts`:
   - `POST /api/stores/:storeId/orders`: создание заказа покупателем (валидация состава заказа и цен по БД).
   - `POST /api/stores/:storeId/orders/:orderId/pay`: эмуляция подтверждения оплаты через Sandbox-шлюз.
   - `GET /api/stores/me/orders`: получение списка заказов для владельца магазина (строгая изоляция по `storeId`).
3. Разработать клиентскую корзину:
   - Боковая панель `CartDrawer.tsx` с подсчетом суммы и управлением количеством.
   - Форма оформления (email, имя, тестовый выбор доставки СДЭК).
4. Проверить сценарии: оформление заказа гостем/покупателем, смена статуса на PAID, отображение заказа в панели владельца.
5. Проверить `npm run lint` и `npm run build`.

## Критерии проверки
- [ ] Таблица `orders` создана в Neon с обязательным индексом по `storeId`.
- [ ] Сумма заказа пересчитывается на сервере по ценам из БД (клиент не может подделать сумму).
- [ ] Владелец видит только заказы своего магазина (изоляция мультитенантности).
- [ ] `npm run lint` и `npm run build` проходят с 0 ошибок.
