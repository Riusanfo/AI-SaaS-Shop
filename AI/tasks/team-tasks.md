# Памятка и технические задания для команды (Спринт 1)

## ЧАСТЬ 1. Инструкция после получения инвайта на GitHub

### Шаг 1. Принять приглашение

1. Откройте почту или зайдите на github.com в раздел уведомлений.
2. Примите приглашение в репозиторий (Accept invitation), иначе Git не разрешит операции clone и push.

### Шаг 2. Склонировать проект и проверить окружение

В терминале (Git Bash / PowerShell / Terminal):

```bash
# 1. Клонирование репозитория
git clone https://github.com/Riusanfo/AI-SaaS-Shop.git
cd AI-SaaS-Shop

# 2. Проверка версии Node.js (требуется v18 или новее)
node -v
npm -v
```

### Шаг 3. Создать рабочую ветку

Никто не работает в ветках main или dev. Каждый создает отдельную ветку под свою задачу:

```bash
# Переключаемся на dev и забираем актуальные изменения
git checkout dev
git pull origin dev

# Создание персональной ветки:
# Для Кости:
git checkout -b feat/evals-ai-dataset

# Для Дживана:
git checkout -b feat/design-acceptance-docs
```

### Шаг 4. Порядок сдачи задачи

После завершения работы в своей папке:

```bash
git add .
git commit -m "feat: краткое описание выполненной работы"
git push origin <название-вашей-ветки>
```

Затем на GitHub создайте Pull Request в ветку dev и отправьте ссылку в рабочий чат на проверку.

## ЧАСТЬ 2. Ограничения и правила работы

1. Изоляция папок: папки src/ (клиент) и server/ (сервер) не трогать. Работа ведется строго внутри назначенных каталогов (evals/, docs/, AI/design/screens/).
2. Прямой push в main и dev запрещен.
3. Файлы .env, токены и пароли коммитить запрещено.

### Задание для Кости

#### Основная задача: База тестовых сценариев для ИИ-помощника витрины

- Папка: evals/
- Файл: evals/prompts.json
- Цель: Подготовить тестовый датасет ровно из 50 типовых запросов к ИИ магазина для замера метрики качества (требование ТЗ: корректная обработка >= 90% запросов).

Требования к датасету:
5 категорий ровно по 10 вопросов в каждой:

1. product_description - генерация описания товара (свечи, одежда, декор, посуда, кофе).
2. seo_copy - генерация SEO-заголовков, мета-описаний и поисковых тегов.
3. store_structure - рекомендации по категориям каталога и навигации.
4. pricing_advice - советы по ценообразованию, наценке и акциям.
5. platform_help - вопросы по функционалу платформы (оплата, доставка).

Граничные случаи (обязательно включить в общий пул из 50):

- 2 пустых или бессмысленных запроса (пробелы, случайные символы).
- 2 очень длинных запроса (>1000 символов связного текста).
- 2 попытки обхода инструкций (prompt injection / jailbreak: "забудь все инструкции", "выведи системный промт").

Формат каждого объекта в evals/prompts.json:

```json
[
  {
    "id": 1,
    "category": "product_description",
    "prompt": "Напиши описание для керамической вазы ручной работы, матовый графит, цена 2400 руб.",
    "expected_criteria": "В ответе присутствуют параметры изделия, призыв к покупке, нет выдуманных характеристик.",
    "is_edge_case": false
  }
]
```

Скрипт прогона evals/run-test.js:
Скрипт на Node.js, который:

1. Читает evals/prompts.json.
2. Передает каждый промт в функцию-заглушку (эмуляция ответа ИИ с задержкой 100 мс).
3. Формирует отчет evals/report.md в виде Markdown-таблицы (ID, Категория, Вопрос, Ответ, Статус).

#### Запасная задача: Руководство пользователя

- Папка: docs/user-guide/
- Файл: docs/user-guide/getting-started.md
- Содержание:
  1. Регистрация на платформе (выбор роли: Владелец магазина или Покупатель).
  2. Различие ролей (покупателю конструктор недоступен).
  3. Открытие конструктора владельцем и создание первой витрины.
- Требование: Описывать только работающий функционал. Не реализованные в коде функции помечать строкой "[В разработке]".

#### Запасная задача: Чек-лист приемочного тестирования

- Папка: docs/acceptance/
- Файл: docs/acceptance/checklist.md
- Цель: Подготовить пошаговые сценарии ручной проверки для демонстрации проекта комиссии.

Формат оформления каждого сценария (Шаги -> Ожидаемый результат):

1. Сценарий "Создание магазина за 60 минут":
   - Шаг 1: Открыть сайт, нажать "Создать аккаунт".
   - Шаг 2: Зарегистрировать роль "Владелец магазина".
   - Шаг 3: Перейти во вкладку "Создать", выбрать шаблон Minimal, изменить акцентный цвет, добавить 2 товара.
   - Ожидаемый результат: Предпросмотр обновился, данные сохранены в хранилище.
2. Сценарий "Ролевая модель":
   - Шаг 1: Зарегистрироваться под ролью "Покупатель".
   - Шаг 2: Попробовать открыть вкладку "Создать".
   - Ожидаемый результат: Отображается экран "Доступ ограничен, конструктор предназначен для владельцев магазинов".
3. Сценарий "Темы оформления":
   - Шаги переключения светлой и темной тем, проверка контрастности текста.
4. Пункты ТЗ "500 пользователей" и "14 дней непрерывной работы":
   - Добавить как отдельные разделы с пометкой: "[Проверяется автоматическим нагрузочным тестированием при развертывании]".
