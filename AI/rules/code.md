# Правила кода и данных

## TypeScript и React
- Строгий TypeScript: запрещено использование `any`, необоснованных `@ts-ignore` и `eslint-disable` (любое подавление линтера требует исчерпывающего комментария).
- Функциональные React-компоненты с хуками.
- Состояние компонентов минимальное; поднимается вверх только тогда, когда это необходимо нескольким компонентам.
- Общие схемы валидации и типы выносятся в `shared/` и реализуются через **Zod**.

## Данные и безопасность (Critical)
- **Изоляция мультитенантности**: любой запрос к данным магазина обязан фильтроваться по `storeId` на уровне базы данных/сервера. Доступ напрямую из маршрута без проверки `storeId` запрещен.
- **Проверка прав на сервере**: скрытая кнопка в интерфейсе не является защитой. Права проверяются на сервере (`requireRole` middleware) для каждой роли (`PLATFORM_ADMIN`, `STORE_OWNER`, `STORE_MANAGER`, `BUYER`).
- **Валидация входа**: входящие данные на каждом эндпоинте проверяются через Zod-схемы.
- **Идемпотентность и безопасность**: вебхуки платёжных систем и доставок проверяют цифровую подпись. Платежи и доставки выполняются исключительно в `sandbox`-режиме.
