# Правила Git и ветвления

## Ветки
- Вся разработка ведётся в ветках формата `feat/...` (например, `feat/auth-flow`, `feat/product-catalog`).
- Прямые коммиты и push в ветки `main` и `dev` **строго запрещены**.
- Изменения попадают в основную ветку только через Pull Request после успешного ревью и прохождения проверок.

## Коммиты
- Сообщения коммитов должны быть понятными и на английском языке (в повелительном наклонении, например: `feat: add store creation form`, `fix: validate storeId in products API`).
- Коммиты должны быть атомарными (одна задача — логичный набор изменений).

## Безопасность
- Запрещено коммитить `.env` файлы, секретные ключи, пароли, токены API и приватные ключи.
- Все чувствительные данные передаются только через переменные окружения.
